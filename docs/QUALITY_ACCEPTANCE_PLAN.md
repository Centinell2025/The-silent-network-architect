# Expert review and acceptance gates

**Publisher:** Beacon of the Eagle LLC — Centinell Suite Defense. Fictional scenario organizations remain separate.

## What is demonstrably verified
- An automated script checks file and student package integrity.
- A second script cross-checks temporal, identity, authorization, sensor and transfer invariants.
- The narrative has mixed benign/suspicious simulated events and a multi-host diagram.

## What is not yet demonstrated
- An investigation performed by an unaffiliated analyst without receiving the answer key.
- Native multi-OS Windows EVTX/Sysmon, Linux auth, packet captures, or disk/memory forensic artifacts captured from an actual controlled lab.
- An HTB-compliant **private write-up with real analysis screenshots for each of the 30 questions**.
- Confirmed grading acceptance for six narrative questions (Q25-Q30).
- Measured experienced-solver time, false-positive rate, or platform acceptance.

## Exit criteria before labeling a submission 'Insane-ready'

1. Reproduce scenario on isolated Windows and Linux test VMs, with authorized activity and complete native captures.
2. Make the investigator discover major events from raw records rather than from pre-labeled `suspicious` fields or a curated timeline.
3. Put at least 10 meaningful decoys in each major investigative stage; test that none produces a second valid exact answer.
4. Have two experienced, independent Blue Team investigators complete blind solves; record completion time and ambiguous questions.
5. Build a private annotated path with reproducible commands, timestamps, independent evidence references and screenshots for each exact answer.
6. Verify question labels, archive integrity, privacy, license rights, download permissions and reviewer instructions before submission.

Do not claim ISO certification, validated malware detection, official status or guaranteed earnings.
